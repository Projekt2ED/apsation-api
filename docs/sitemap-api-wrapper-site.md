## 1. 已确认前提

- 业务方向：`ToB`
- 第一版：`不做在线充值`
- 第一版：`必须有可用 Playground`

## 2. 顶层结构

站点建议拆成 3 层：

1. 官网层：负责获客、解释能力、承接咨询
2. 控制台层：负责客户登录后接入、调试、查看日志
3. 运营后台层：负责客户开通、模型权限、公告和排障

## 5. 运营后台 Sitemap

如果第一版直接复用底层中转平台后台，品牌站可以先不单独开发完整后台，只补必要配置页或内部脚本。

### 5.1 必须能完成的运营动作

- 开通客户账号
- 手工加额度或修改配额
- 开通/关闭模型权限
- 管理 Key
- 查询日志和任务
- 发布公告
- 修改 FAQ
- 配置 Playground 示例

### 5.2 若需要自定义后台，建议最小页面集

- `/admin/customers`
- `/admin/customer/:id`
- `/admin/model-access`
- `/admin/announcements`
- `/admin/faq`
- `/admin/playground-presets`
- `/admin/logs`

## 6. 关键页面说明

### 6.1 首页

首页不做“价格驱动”叙事，改成“能力与交付驱动”叙事。

建议模块顺序：

1. Hero：一句话说明平台定位
2. 能力矩阵：对话、图像、音频、视频、向量
3. 协议兼容：OpenAI、Anthropic 等
4. 接入流程：申请开通、Playground 验证、Key 接入
5. 模型展示
6. 最新公告
7. FAQ 摘要
8. 联系商务

### 6.2 Playground

这是第一版最重要的页面，需要避免做成只有一个文本框的假操场。

至少分 6 个模式：

- Chat
- Responses
- Messages
- Images
- Audio
- Video / Tasks

每个模式至少要有：

- 模型选择器
- 请求参数表单
- 请求体预览
- 返回结果区
- `curl` / `Python` / `JavaScript` 示例

### 6.3 模型页

模型页分两层：

- 官网模型页：给未登录客户看“支持什么”
- 控制台模型页：给已登录客户看“我能用什么”
